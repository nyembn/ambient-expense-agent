# Agent Spec

## Overview
The Ambient Expense Agent will be an event-driven ambient expense agent that acts as an automated triage queue. It will process incoming expense report submissions and route them based on the transaction value.

## Assumptions
- **Input Format**: Expense report which arrives as a JSON event.
- **Routing**: Route the expense report based on the transaction value:
  - Expenses under $100 are auto-approved.
  - Expenses of $100 or more are reviewed by the agent and paused for human approval.
- **Deployment target**: Prototype first (no cloud deployment, local testing only).
- **Integration**: Local storage or console printout.
- **Model**: Standard Gemini model for ADK.

## Example Use Cases
### Case 1: Auto-approving a Low-value Expense
- **Input**: A JSON event with an expense of $45.00.
- **Output**: Auto-approved log/status.

### Case 2: Routing a High-value Expense for Review and HITL Approval
- **Input**: A JSON event with an expense of $150.00.
- **Output**: Escalated to LLM review agent, followed by human-in-the-loop (HITL) approval request.

## Tools Required
- None (uses internal routing and LLM agent for review).

## Constraints & Safety Rules
- Must not leak or process PII other than what is necessary for expense tracking.
- Must flag inputs that are clearly not expenses.

## Success Criteria
- Accurately routes expense reports based on value thresholds.
- Correctly parses and flags high-risk/high-value expenses in evaluation.
